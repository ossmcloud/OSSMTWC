NetSuite back-office forms

For Towercom staff: what Nexus adds to the standard NetSuite record forms.

Staff work in two places: the Nexus portal pages and the native NetSuite records. Changes made in one are not repeated in the other's screens, but the data is the same.

Records you can't edit in NetSuite

Some records can only be changed through the portal. On these:

  • creating a record shows "this record cannot be manually entered!";
  • clicking Edit returns to view mode with a Read-Only Record banner.

Some other records can be edited but not created ("You do not have permission to create this record. This record is EDIT ONLY."). Use the portal page for those records.

Company and Profile

Company

  • Open Company opens the portal Company Profile.
  • The TL Company ID (COM-0000123) is set automatically when the company is created.
  • When an EL / PL / PI insurance status is Active, its expiry date is mandatory and must be in the future.

Profile

  • View Certs History lists all the person's certificate files.
  • Open Company opens the person's company in the portal.
  • When a certificate status is Active, its expiry date is mandatory and must be in the future.
  • Setting the Safe Pass status to Pending sets the person's accreditation status to Pending.

The accreditation status change date is stamped automatically on both records.

Approving files and insurance

On a TL File record (view mode):

  • Open Record opens the record the file belongs to.
  • For a company file with status Pending: Approve File, or Approve Insurance File for insurance documents.

Approve File

The Verify File dialog shows the file. Click Accept (status Received) or Reject (status Rejected).

Approve Insurance File

The Verify Insurance File dialog shows the file and asks for:

  • New Expiry Date and Insurer;
  • for each of EL, PL, PI: switch on Apply for the covers this certificate includes, then enter Limit, Status and Currency;
  • Restrictions.

Accept writes the details to the company, marks the previous insurance file Superseded and this one Received.

Files on other records

Records with attachments show View Files and Upload File, and a Twc Files list on the Media tab.

Site

  • The record name is set automatically to <Site ID> : <Site Name>.
  • Sites are copied to the FSA mobile app automatically.

Equipment and Equipment Library

  • Equipment opened from the portal's Add Equipment button arrives with the site pre-filled and locked.
  • An Equipment Library entry created from an SRF line (Lib link) copies the class, make, model, description, dimensions, weight and voltage type, and starts as Draft. Equipment Class, Equipment Type and Library Entry Status are mandatory.

SRF and SAF records

  • SRF record: Open SRF opens the portal page.
  • SAF record: Open SAF opens the portal page; the Conditions of Access are shown on the form.
  • Records migrated from Radix show the banner "This transaction was migrated from Radix".
  • Authorised users have Delete SRF / Delete SAF, which remove the request and its related records. Use with great care.

Infrastructure and inspections

  • Each infrastructure type has its own form. Choosing the form sets the type; records always open in the form of their type.
  • Changing Last Service Date sets Next Aircon Service to one year later.
  • Saving an Inspection with a fall-arrest certificate date updates the infrastructure: last fall-arrest cert date, next date (one year later) and fall-arrest status.
  • A nightly job flags the fall-arrest status of infrastructure whose next certificate date has passed.

Power readings

The Power Readings tab on a power reading lists the other readings for the same meter.

  • Tick one reading in Select to update latest and click Update Latest status to make it the latest. The previous latest reading is moved to another status.
  • On save, Nexus works out the days since the last reading, the day / night / peak unit usage, the kWh usage and the kWh amp check, from the meter's previous reading.
  • A new reading also updates the power meter's last reading details.

Tax details on transactions

On purchase and sales transactions and journals:

  • Picking a line project copies it to the Customer:Project (Name on journals).
  • With Tax Details Override ticked, choosing a tax code fills the rate and amount; changing basis or rate recalculates the amount.
  • On save, the tax details must match the lines (total basis, rate of the tax code, amount = basis × rate). Otherwise "Tax Details validation failed" lists the differences.
  • Vendor bills from a PO can't bill more than is left on the PO; the line is corrected back. A PO line can't be reduced below what's already billed.
  • If STE Transaction Type is empty, you get a one-time warning. Fill it in, or click Save again if it should stay empty.
